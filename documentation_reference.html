Reference

This section provides detailed reference materials for configuring the Urban360 plugin, understanding its output structures, and resolving common issues.

Configuration Parameters

These parameters are configured in Project Settings > Plugins > Urban360, not in the actor's Details panel:

Parameter (Project Settings > Plugins > Urban360) Default Description
Resolution (internal: AtlasWidth) 1024 Pixel width of each eye's 360° image; the height is always half of it. Stereo stacks both eyes into one file, so 1024 writes a 1024×1024 file holding two 1024×512 views. Range 512–4096. The released Urban360 Dataset was captured at this setting; the experiments in the paper were run at 1920.
Capture Type Stereo Stereo (both eyes) or Mono.
Capture Count Single A single centre node, or a 9-node isotropic cluster (Group).
Capture Height 160 cm Camera height above the actual ground surface (re-measured per point via a downward raycast).
Capture Color / Depth / Normal / Semantic Color, Depth, Normal on; Semantic off Per-modality capture toggles.
Adaptive Exposure On Meters the scene once per panorama and freezes that EV across all 168 slices. Off uses a fixed bias of 2.0.
Exposure Target Grey 0.06 Master brightness target for colour (EV = log2(metered / target)).
Exposure Min / Max EV −6.0 / 2.0 Exposure clamps.

Stereo baseline

Note: the stereo baseline is fixed at 6.4 cm total (±3.2 cm per eye) through the DG.EyeSeparation console variable; it is not a Details-panel field.

Semantic segmentation

Semantic segmentation is implemented in the plugin but is not part of the v1 release. It will be enabled in a future update, together with a semantic sample and its class taxonomy.

Output Format

The plugin writes three separate FP16 EXR files per view, not one multi-channel file. Each file is W × W, HALF float, ZIP-compressed, RGBA. The two stereo eyes are stacked in each file (left on top, right on bottom), so each eye is a W × W/2 equirectangular image.

  • Color ({scene}_pos5_color.exr): ACES-tonemapped LDR in linear light (no sRGB gamma), range [0, 1], alpha = 1. Apply an sRGB transfer before display or before feeding sRGB-trained backbones.
  • Depth ({scene}_pos5_depth.exr): R = G = B = radial distance (metres) to the first surface the ray meets. Sky = 65504.0, invalid = 0.0 (use valid = depth < 65504.0). Alpha = translucency mask (1 = opaque, 0 = a translucent surface came first).
  • Normal ({scene}_pos5_normal.exr): RGB = unit surface normal in CV coordinates, derived from the depth. Alpha = validity mask (1 = valid, 0 = invalid).
  • Coordinate frame: CV standard (X-right, Y-down, Z-forward), metres.
  • Camera Pose: {scene}_manifest.csv, one row per node, columns: Filename, PosX, PosY, PosZ, Qw, Qx, Qy, Qz, ExposureEV, DepthConvention, TranslucentElements, TranslucentPct, StitchParams, RenderParams. Position in metres, unit quaternion in WXYZ order, CV frame. Pose is not stored in the EXR and not in a metadata.json.
<Environment>/<SceneID>/
    <SceneID>_pos5_color.exr   <SceneID>_pos5_depth.exr   <SceneID>_pos5_normal.exr
    <SceneID>_manifest.csv

Bundled reference documents

The plugin ships two authoritative reference documents: Urban360_Dataset_Architecture.md (the output contract) and Urban360_Dataset_ERRATA.md (paper-versus-release differences). Both ship with the plugin and will be distributed alongside the dataset.
