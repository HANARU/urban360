Reference

This section lists the settings of the Urban360 plugin and describes the files it writes.

Configuration Parameters

Capture settings are made on the three pages of the Capture Tool and take effect when you press Apply Settings. The same values are stored in Project Settings > Plugins > Urban360, where a few have a different name, given in parentheses below. The Lighting Standard and the weather adjustments are on the neighbouring page, Urban360 Calibration; the weather adjustments also appear under Calibration on the Env page.

Points page

SettingDefaultDescription
Spline Spacing (Step Size) 500 cm Distance between points along each road spline. Must be at least 1 cm.
Road Width 1000 cm Width across which points are spread. Set for each spline.
Safety Radius 35 cm A point with a wall, tree or other obstacle within this radius is dropped.

Capture page

SettingDefaultDescription
RGB / Depth / Normal / Semantic (Capture Color / Depth / Normal / Semantic) RGB and Depth on; Normal and Semantic off Which images to write, listed under Capture Mode, where All ticks every type. At least one must be on.
Capture Stereo (Capture Type) Stereo Stereo writes both eyes into one file. Mono writes one eye from the rig center and takes about half the time.
Capture Count Single Single captures one image per point. Group captures a nine-node cluster around it, which takes nine times the data and the time.
Camera Height (Capture Height) 160 cm Camera height above the actual ground under the point, measured again for every point.
Local Step (Grid Distance) 10 cm Spacing of the Group cluster. Unused with Single.

Env page

SettingDefaultDescription
Time of Day / Weather Day / None Day or Night. The weather list offers None, Rain, Snow and Fog.
Env Name (Environment Name) Default Name of the output folder. If it names a time of day or a weather, such as Day_Clear, Setup & Verify checks that it matches the condition applied.
Start Index 1 First SceneID a run captures, which is how a stopped run is resumed. New points are numbered from it as well.
Current Path (Root Data Path) <Project>/Saved/Urban360Data Output root, chosen with Browse Path.
Resolution (internal: AtlasWidth) 1024 Pixel width of each eye's 360° image; the height is half of it. Stereo stacks both eyes into one file, so 1024 writes a 1024×1024 file holding two 1024×512 views. Even values from 512 to 4096; above 2048 Setup & Verify warns about memory. The Urban360 Dataset is captured at 1024; the experiments in the paper were run at 1920.

Urban360 Calibration

SettingDefaultDescription
Day Lighting / Night Lighting (Lighting Standard) Day: sun 3 lux at 60° elevation and −15° azimuth, 6500 K, sky light 1.0
Night: sun 0.5 lux at 0° elevation, sky light 2.0		 The light every capture is taken under, in place of the level's own sun, sky light, sky and fog, so that all worlds are shot under the same light. The weather scales this sun. A changed standard raises the note E014, and the manifest records what was rendered (sun, skyl).
Hide Practical Lights Off On also hides the level's point, spot and rect lights. Off keeps street lamps and other practical lights in the shot.
Use Level Post Process Off On lets the level's PostProcessVolume grade the Color images (color temperature, saturation, contrast, curves). Off gives every world the same grading.
Weather Fog Scale 1.0 Scales the fog of the active weather.
Weather Sky Light Boost 1.0 Scales the sky light under bad weather. Earlier versions defaulted to 30, and the value is saved on each PC, so check it on a machine that ran an older version.

Project Settings only

SettingDefaultDescription
Stream Settle Timeout 10 s At every point, the longest the tool waits for the world to finish loading and for shaders to compile (Urban360 > Capture).
Semantic Data Table The plugin's own table The table of categories (Urban360 > Semantic). To change the categories, duplicate the plugin's table into your project and set the copy here; updating the plugin replaces its own table.

Exposure settings do not change the image

Adaptive Exposure, Exposure Target Gray and Exposure Min/Max EV are advanced settings marked record only. They change only the ExposureEV value the manifest records. Every Color image is tonemapped at a fixed exposure of 1.0, so pixel values can be compared across points, scenes and conditions without normalization. Night images therefore come out dark; brighten them afterwards to look at them.

Stereo baseline

The stereo baseline is fixed at 6.4 cm (±3.2 cm per eye) through the DG.EyeSeparation console variable; it is not a field in the tool. Mono renders from the rig center, and StitchParams records eyesep (0 for Mono). Mono captures made before 12 October 2026 have no eyesep and were rendered 3.2 cm to the left of the recorded position.

Semantic labels

With Semantic on, the plugin writes an 8-bit RGB PNG in which the color of a pixel is its category; the category number itself is not stored. The default category table is based on Cityscapes and is not final, so it is not listed here. Labels are set up for each level, by assigning categories to actors, by mesh-path rules, by actor-class mappings and by landscape paint layers. Setup & Verify does not pass while objects the camera can see have no label. MASS crowds and traffic exist only during the capture, so this check cannot see them.

Output Format

For every capture position the plugin writes the files below into the scene folder and one row into the scene's manifest. The EXR files are W × W, HALF float, ZIP-compressed, RGBA, one file per image type rather than one multi-channel file. Stereo stacks the two eyes in every image file (left on top, right on bottom), so each eye is a W × W/2 equirectangular image.

  • Color (<SceneID>_pos5_color.exr): ACES-tonemapped LDR in linear light (no sRGB gamma), range [0, 1], alpha = 1. The exposure is fixed at 1.0 whatever ExposureEV says, so pixel values compare directly across points, scenes and conditions. Rendered without Lumen, so there is no bounced light. Apply an sRGB transfer before display or before feeding sRGB-trained backbones.
  • Depth (<SceneID>_pos5_depth.exr): R = G = B = radial distance (meters) to the first surface the ray meets. Sky = 65504.0, invalid = 0.0 (use valid = depth < 65504.0). Alpha = translucency mask (1 = opaque, 0 = a translucent surface came first). A translucent material that writes its own depth (Output Depth and Velocity) stays at A = 1; its distance is still correct.
  • Normal (<SceneID>_pos5_normal.exr): RGB = unit surface normal in CV coordinates, derived from the depth. Alpha = validity mask (1 = valid, 0 = invalid). Invalid pixels are the sky and pixels whose orientation could not be measured, written as RGB (0, 0, 0), so normal.A == 0 is a larger set than depth >= 65504. Normals near the zenith and the nadir are measured like everywhere else.
  • Semantic (<SceneID>_pos5_semantic.png, optional): 8-bit RGB, one color per category, with the eyes stacked like the EXR files.
  • Depth behind translucency (<SceneID>_pos5_depth_behind.exr, optional): written only when the console variable DG.Depth.WriteBehindLayer is 1. It records the opaque surface behind glass and water, for work on multi-layer depth.
  • Pixel to direction: pixel-corner convention. In an eye image of width W and height H = W/2, pixel (x, y) looks along longitude θ = x / W · 360° and polar angle φ = y / H · 180°. Row 0 is exactly the zenith and the last row is half a pixel above the nadir; column 0 faces the rig's forward direction, and the view turns right as the column grows. Reading with the common (x + 0.5) / W convention shifts every direction by half a pixel (0.18° at W = 1024).
  • Coordinate frame: CV standard (X-right, Y-down, Z-forward), meters.
  • Camera Pose: <SceneID>_manifest.csv, one row per completed position, columns: Filename, PosX, PosY, PosZ, Qw, Qx, Qy, Qz, ExposureEV, DepthConvention, TranslucentElements, TranslucentPct, StitchParams, RenderParams. Position in meters, unit quaternion in WXYZ order with Qw ≥ 0, CV frame. Pose is not stored in the EXR and not in a metadata.json. ExposureEV is what the exposure meter asked for, not what was applied.

A position that stalled or whose files could not all be written gets no row, and a row from an earlier run of the same position is dropped with it. Files in a scene folder without a manifest row are therefore incomplete. Images and manifests are written to a .part file first and renamed when complete, so a file under its final name is never cut short.

<Current Path>/<Env Name>/
    _run_<date>-<time>.txt
    <SceneID>/
        <SceneID>_pos5_color.exr   <SceneID>_pos5_depth.exr   <SceneID>_pos5_normal.exr
        <SceneID>_pos5_semantic.png
        <SceneID>_manifest.csv

Provenance keys in the manifest

StitchParams and RenderParams hold key=value pairs separated by semicolons, so new keys never change the number of columns. They record the values actually rendered, not the values requested.

KeyMeaning
h, vStitchParams. Horizontal and vertical step between slices, in degrees (15 and 30).
fovStitchParams. Field of view each slice was rendered at, in degrees (40). 30.0 marks a capture made before October 2026, with the stitching defects listed below.
ov, blendh, blendv, guardh, guardvStitchParams. Requested blend width, the horizontal and vertical blend widths actually applied, and the guard added to each strip, in degrees.
tau, w, ssStitchParams. Edge threshold of the depth stitching, Resolution, and whether Color averages over each pixel's area (1) or samples its center (0).
eyesepStitchParams. Distance between the eyes in cm; 0 for Mono, which renders from the rig center.
reflRenderParams. The project's reflection method. This is a project setting only; it does not mean Lumen reflections ran.
lumenfrontRenderParams. Whether the plugin switched on Lumen front-layer reflections for the capture, which it does when the project's reflection method is Lumen. It has no effect, because Lumen does not run in scene captures.
ssrRenderParams. Whether screen-space reflection was on. With 1, reflections on water and glass can differ from slice to slice; this key, not refl, says whether reflective pixels carry that artefact.
colorgi, colorreflRenderParams. Global illumination and reflection method the Color slices actually used; none by default.
colorvs, colorwarmRenderParams. An experimental option, off by default (colorvs=0), and the number of frames each Color slice was rendered before it was read.
dfaoRenderParams. Distance-field sky occlusion in the Color pass. 0 in current captures; with it on, shade came out black.
exposureRenderParams. fixed1: the Color image was rendered at exposure 1.0.
levelppRenderParams. Whether the level's PostProcessVolume graded the Color image (Use Level Post Process).
sun, skylRenderParams. The sun actually rendered, as illuminance in lux at elevation and azimuth (after the weather scaling), and the sky light intensity.
substrateRenderParams. Whether the project uses Substrate materials.
planaroff, bloom, localexp, lightshafts, fringe, dofRenderParams. Number of planar reflection actors hidden during the capture, and whether bloom, local exposure, light shafts, chromatic aberration and depth of field were on. The screen-wide effects are turned off because each slice is its own screen.

Telling capture versions apart

Captures made with earlier versions of the plugin have known defects. The manifest shows which version a capture came from:

In the manifestWhat it means
fov=30.0 and no blendv in StitchParamsStitched before October 2026. One row reads a direction up to 0.26° off (row 128 of each eye at a Resolution of 1024), Color can show horizontal lines at the slice boundaries (±15, ±45 and ±75° elevation), and fine periodic detail can turn into moiré.
No dfao, or dfao=1, in RenderParamsSurfaces the sun does not reach receive no sky light, so shade can be near black, and rain, snow and fog keep sharp sun shadows with black interiors.
Captured before 10 October 2026Normals that could not be measured are marked valid (a vertical normal with A = 1), and the quaternion sign varies (flip all four components where Qw < 0).
No eyesep in StitchParamsMono was rendered 3.2 cm to the left of the recorded position, and normals within 8.6° of the zenith and nadir were blended toward vertical.
Night capture in Rain, Snow or Fog made before 12 October 2026 (no manifest key; a row without sun in RenderParams is older still)The sky dome kept its daytime colors, a blue-orange sky with a bright sun disc above a night scene, and the shade was lit more than the Night Lighting standard says. Do not use these as night data.
