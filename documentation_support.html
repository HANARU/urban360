Support

If you encounter issues while using the Urban360 plugin or need to request additional resources, please refer to the solutions below or contact our team directly.

Troubleshooting & FAQs

Problem codes

The capture tool reports every problem with a short code, such as S007 or C001. The code appears in the Setup & Verify window, in the notifications at the bottom right of the editor, in the Output Log (as [C001] ...) and in the run report written next to your data. Urban360_Troubleshooting.md in the plugin folder explains every code: what happened, why, and what to do. The letter says where a problem comes from:

LetterArea
SInstalling the plugin and preparing a capture
MSemantic labels
EEnvironment: time of day, weather, sky and lights
CA capture run
DDepth, stitching and rendering
PCapture points and saving the level
OOutput files
XInternal errors

Each code also has a severity. Block: Setup & Verify does not pass until it is fixed. Error: data was not written, or was written wrong. Warning: data may be worse than it should be. Note: not a fault, but good to know. When you report a problem, send the run report and the editor log (Saved/Logs/<ProjectName>.log).

Using the plugin

Play ends at once with "Nothing to capture" (S007).

Every point has its Capture Target box cleared, or every ticked point comes before Start Index. Press Target All on the Points page, or lower Start Index on the Env page.

A run stopped, or some points were skipped (C001).

Read the run report (_run_<date>-<time>.txt). Its Resume line gives the Start Index that continues a stopped run, and its Incomplete line lists the points that stalled for 120 seconds or whose files could not be written. Those positions have no row in the manifest. Capture them again: every Play captures all points whose Capture Target box is ticked from Start Index on, so set Start Index, or use the Point List to shoot only those points.

Shade comes out almost black (E015).

Captures are taken without Lumen, so shade is lit only by the sky light of the Lighting Standard. When that is too low for a level's materials, the run raises the note E015, and the run report's Shade line gives how much of the image came out near black. If the shade should be visible, raise Sky Light under Project Settings > Plugins > Urban360 Calibration > Lighting Standard (try 2 or 3) and capture a point again. In one project with Substrate turned on, raising the sky light changed nothing, and turning Substrate off was the known way out. Captures made before 9 October 2026 had black shade for a different reason; see Telling capture versions apart.

Capture points are off the ground (P006, C007, C008).

A capture point marks the spot on the ground the camera stands over. Points moved by hand or dropped onto other objects can sit above or below it. Setup & Verify lists them and offers to put them back; answer Yes and save the level. If there is no ground within reach under a point (C007), move the point onto the ground. In a World Partition level, wait until the level has finished loading before checking: right after opening, some ground has no collision yet.

Setup & Verify reports objects without a label (M003).

With Semantic on, every object the camera can see needs a category. An unlabelled object would be written as 0, which looks like a valid label to anything that reads the files later. Click a row in the Setup & Verify window to select those objects, then assign a category on the Semantic page. In a World Partition level, load every region first.

The editor slows to a crawl or closes at a high Resolution (S011).

The images of one point take about 1 GB of memory in stereo at a Resolution of 1024, 5 GB at 2048 and 18 GB at 4096 (mono about two thirds of that), on top of what the level itself needs while playing. Lower Resolution on the Env page and press Apply Settings.

Reflections on water or glass differ from slice to slice.

Check the manifest's ssr key in RenderParams, not refl. When the project's reflection method is Lumen, the plugin turns screen-space reflection off for the capture (ssr=0): water and glass then reflect only reflection captures and the sky light, and no slice-to-slice difference arises. When the project uses screen-space reflection, the plugin leaves it on and warns (D003, ssr=1). Each slice then reflects only what is inside its own view, so reflections can differ between neighbouring slices. Lumen itself does not run in scene captures, so refl=lumen_hardware does not mean the reflections were traced.

Can the capture project be packaged as a game?

No. Setup & Verify sets the level's GameMode to the capture GameMode, and the capture classes live in an editor-only module that is not packaged, so such a level cannot run in a packaged build. Use a separate copy of the project for the game, or remove the GameMode override and the plugin first. See What the tool changes in your project.

Reading the data

The images look almost black.

Color is stored in linear light, not sRGB. Apply an sRGB transfer function before display or training. Do not apply an inverse sRGB; that crushes the data.

ExposureEV differs between captures, but the images do not. Night images are very dark.

Every Color image is rendered at a fixed exposure of 1.0. ExposureEV only records what the exposure meter asked for, so two captures of the same pose can differ in ExposureEV while their images are the same. Night images come out dark for the same reason. That is expected; brighten them afterwards to look at them.

Depth has huge values around 65504.

That is the sky / at-infinity sentinel, not a distance. Mask it: valid = depth < 65504.0. Projection failure is a separate value, 0.0.

A W × W EXR looks vertically squashed when read as a panorama.

The file packs two eyes (left on top, right on bottom). Split it into halves, then treat each half as a W × W/2 ERP.

Depth resampled to another resolution shows surfaces that are not there.

Never bilinearly resample depth; use nearest-neighbour, so a discontinuity does not average into a surface that is not there.

Two different alpha channels.

depth.A is a translucency mask (0 = a translucent surface came first); normal.A is a validity mask (0 = the sky, or an orientation that could not be measured). They mean different things and do not coincide. Because normal.A == 0 covers more than the sky, take the sky mask from the depth (depth >= 65504), not from the normal.

Release & Updates

Recent updates to the Urban360 documentation and project landing page.

October 19, 2026

  • Correction: Captures do not use Lumen. In Unreal Engine 5.7, scene captures run without Lumen global illumination and Lumen reflections, and the plugin never turned them back on, so every capture, including the data used in the paper, was rendered by the deferred renderer without bounced light. Earlier versions of this site described the rendering as Lumen-based. Dense GT on glass and water comes from the plugin's first-surface depth pass, and the reported results are unaffected.
  • Landing Page: The rendering description and the reflection figure are corrected: the lower slice-frequency peak on water comes from turning screen-space reflection off, not from Lumen tracing. The plugin is now described as spline-based rather than as a single drop-in actor, and the contribution list no longer claims to be the first to export these modalities together.
  • Landing Page and Documentation: The editor screenshots now show the current Capture Tool, its Env and Capture pages, and the Plugins browser.
  • Documentation: Getting Started is rewritten for the current plugin: Windows 64-bit only, Niagara and Datasmith Content as dependencies, memory figures in place of a GPU recommendation, the extra restart for DBuffer decals, a Quick Start through the Capture Tool, and what the tool changes in a project.
  • Documentation: Reference lists the settings by their names in the tool, with corrected defaults (Normal is off by default), the exposure settings marked as record only, and the Lighting Standard. It adds Semantic labels, the pixel-to-direction convention, the new manifest keys and a table for telling capture versions apart.
  • Documentation: Support explains the problem codes and adds FAQs on resuming runs, dark shade, fixed exposure, points off the ground, labels, memory and packaging. The reflection FAQ now relies on the ssr key instead of recommending Lumen reflections.

October 5, 2026

  • Landing Page: The Paper, Plugin Binary and Dataset buttons are now shown as disabled until release instead of linking nowhere.
  • Landing Page: References to CARLA, PanoCity (PanoVGGT), DAP and DA² now link to their arXiv pages instead of Google Scholar searches.
  • Documentation: The installation page now states that Urban360.zip is not publicly available yet and points to the early-access form below.

September 11, 2026

  • Landing Page: The paper has been accepted at AsiaSim 2026. The status notice, the BibTeX entry and the notes on the unreleased resources now say so.

September 4, 2026

  • Documentation: Fixed the mobile layout. The sidebar now stacks above the content and the page scrolls as a single document, and wide tables and code blocks no longer overflow the screen.
  • Landing Page: Updated the geometric validation to cover the full release: 10,080 views across all three scenes, replacing the earlier 5,128 views across two.
  • Landing Page: Published the site at hanaru.github.io/urban360.

September 3, 2026

  • Documentation: Confirmed the distribution format. The plugin ships as a compiled binary (Urban360.zip) with no build step, so Blueprint-only projects are supported and the source is not published.
  • Documentation: Added three editor screenshots supplied by the authors, covering the Dataset Generator panel, the Plugins browser and the Project Settings page.

September 2, 2026

  • Documentation: Updated configuration parameters and exact EXR output specifications based on actual plugin inspection.
  • Documentation: Corrected linear-light color information and clarified semantic feature status.
  • Landing Page: Added high-resolution qualitative comparisons (Fig 1, 2, 3) and stereo reprojection error validation.
  • Landing Page: Added notice clarifying the released dataset resolution (1024) vs. the original paper experiments (1920).

September 1, 2026

  • Documentation: Split documentation into Getting Started, Reference, and Support layers for better readability.
  • Landing Page: Initial website layout completed.
